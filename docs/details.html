Experiment 01

Technical details and operational telemetry

This page keeps replication data available without asking every reader to understand tokens, cache behavior, or agent-loop internals before they understand the experiment.

Terms used in the results

Run / attempt

One fresh agent context working on one language variant. Attempts do not share memory.

Pass

The final service satisfied the full external behavioral verifier, including concurrency, stale writes, deletion, errors, and regressions.

6/6 passed

Six separate agent attempts were run in that condition and all six passed. This is not a count of test cases.

Agent step

One model action in the linear mini-swe-agent loop. It can contain shell commands, inspection, edits, or verification work.

Output tokens

Tokens generated by the model. This is a rough measure of response volume, not code quality.

Cache hit rate

The share of input tokens served from the provider cache. It mostly matters for cost and runner debugging.

A perfect observed pass rate does not imply a perfect underlying success rate. The 95% Wilson lower bound is about 57% for 5/5, 61% for 6/6, and only 21% for 1/1. The all-pass result prevents estimating a difference in observed accuracy, but it does not prevent comparing continuous outcomes such as steps, tokens, cost, and time. Five runs per language across two related tasks provide descriptive comparative estimates, but still leave wide uncertainty and limited external validity.

Known limitations

This is one model snapshot, one bash-only agent scaffold, related backend contracts, and a small number of attempts. It does not test long-term maintenance, React or browser applications, editor/LSP feedback, dependency migrations, or human review. The balanced cohort now includes five valid runs per language across two brownfield tasks; broader task categories and more repetitions remain pending.
