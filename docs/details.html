Technical details and paired uncertainty

This page keeps replication data available without asking every reader to understand tokens, cache behavior, or agent-loop internals before they understand the experiment.

Terms used in the results

Run / attempt

One fresh agent context working on one language variant. Attempts do not share memory.

Pass

The final program satisfied all twelve checks in the shared behavioral verifier, including exact arithmetic, chained conversion, rounding ties, and the rejection surface.

10/12 passed

Twelve separate agent attempts were run in that condition and ten passed. This is not a count of test cases.

Agent step

One model action in the linear mini-swe-agent loop. It can contain shell commands, inspection, edits, or verification work.

Model rung

A fixed model and effort setting. The study repeats the same task at more than one rung, because whether the language matters may depend on how capable the agent is.

Output tokens

Tokens generated by the model. This is a rough measure of response volume, not code quality.

The model, effort, agent scaffold, instruction bytes, language runtime versions, verifier bytes, and per-run budget were held fixed across languages. Each run began with a fresh context, and the randomized schedule was fixed before launch and executed without reordering.

Why the task changed for v0.7

Through v0.6 the benchmark had a ceiling: all 36 prospective attempts passed, so every measured language difference in correctness was exactly zero by construction and no interval could be estimated. v0.7 introduces money-rollup, a four-file brownfield refactor from floating-point money handling to exact rational arithmetic, with shortest-path currency conversion and ambiguity rejection, ancestor rollups, half-to-even per-entry rounding, and a large rejection surface. Calibration is green: the reference solutions pass every check, all four starters fail the identical eight checks, and four seeded sabotages are caught with identical failure sets in every language. Unlike the earlier families, this one ships a developer-only test harness so hidden expectations are not readable from the workspace.

Twelve attempts per language is enough to break the ceiling but not enough to resolve small correctness differences. The Python versus Go pass-rate interval touches zero rather than clearing it, which is exactly the case that more attempts would settle. Rollouts that ended in a runner exception are recorded in the ledger and excluded from scoring as infrastructure rather than counted as failures.

Known limitations

This is one model snapshot, one bash-only agent scaffold, one hard task family, and twelve attempts per language on the reported rung. It does not test long-term maintenance, browser applications, dependency migrations, or human review. Language is a treatment bundle that includes file topology, toolchain, and ecosystem differences, so a step difference is not evidence about syntax. A different hard task could rank the languages differently.
