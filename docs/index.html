Does your programming language change how well AI codes?

Same task, same model, same agent, fresh context every run. Only the language changes. Over 24 runs per language on one hard refactor, Python passed every attempt and JavaScript failed a quarter of them, while Go spent about 1.5 more agent steps per attempt than either.

What the data says

What the numbers show

Python finished everything

Python passed all 24 attempts. JavaScript passed 18, and that gap is real: the interval for the difference excludes zero, as does the smaller gap between Python and Go. TypeScript at 22 sits between them without separating from either. So there is a correctness signal here, and it is not the one a type checker would predict.

Compiled languages took more steps

Go needed about 1.5 more agent steps than Python or JavaScript, and TypeScript about 0.7 more. Both intervals clear zero, and both languages also cost the most tokens, seconds, and money per attempt. The compile step is the obvious suspect: the two languages with a build are the two expensive ones.

A weaker model fails everywhere

The same task run on a weaker model rung passed 0/25 attempts, in every language. No language rescued it. Whether a language matters at all seems to depend on the agent already being strong enough to be in the game.

What would change this

This is one task family, one model snapshot, and one bash-only agent scaffold. The language is a bundle that also includes its toolchain, file layout, and ecosystem, so none of this is a claim about syntax. The first half of this cohort ranked Go worst on correctness and the second half did not, which is a fair warning about how far twelve attempts can be trusted.

Every paired contrast, the per-case failure breakdown, and the weaker-model cohort are in the written report.

Extra notes

Method and task

The task

A four-file command-line reporting tool has to stop doing money math in floating point. The agent switches to exact arithmetic, converts currencies along the shortest rate path and rejects ambiguous ones, totals every parent account, rounds half-to-even per entry, and rejects about thirty kinds of malformed input. The starter code fails eight of the twelve hidden checks in every language.

Why this task

Earlier rounds were too easy. Every language passed everything, which pins each difference at exactly zero and answers nothing. This one fails often enough to compare, which is the whole point of replacing it.

Calibration

Before any paid run: reference solutions pass every check, the four untouched starters fail the identical eight checks, and four seeded sabotages are caught with identical failure sets in every language. Instructions are byte-identical across languages and the hidden expectations are not readable from the workspace.

Uncertainty

Intervals are 95% percentile intervals from a fixed-seed 20,000-resample paired bootstrap over matched attempt blocks. The strong rung was collected in two batches of 48; the second ran because the first left Python versus Go touching zero, so that continuation was outcome-dependent and the report says so.
