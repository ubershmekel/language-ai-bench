The practical choice

Match the language to the project’s half-life.

01

New app expected to grow

Choose TypeScript

No observed success penalty, fewer agent steps, and compiler feedback for the next edit.

02

Existing multi-file app

Choose TypeScript

Static contracts provide useful insurance when schemas and behavior cross module boundaries.

03

One-off or throwaway

JavaScript is reasonable

Skip setup and compile latency when future maintenance genuinely does not matter.

Strongest signal

TypeScript used 6–10% fewer agent steps and 4–7% fewer output tokens—without changing final correctness.

Visible tradeoff

TypeScript’s compile/test loop took longer in agent wall time. That overhead was about 26–46% in these small samples.

What it cannot prove
