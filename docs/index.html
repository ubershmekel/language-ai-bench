Does your programming language change how well AI codes?

One coding agent, one hard task, four languages, and a hidden verifier that grades only behavior. Python finished every attempt; JavaScript failed a quarter of them. The gaps in effort were wider still, with Go needing about 1.5 more steps per attempt than Python or JavaScript.

The question

If the task, tests, model, and agent all stay fixed, does changing the programming language change whether the agent succeeds, or how much work it takes to get there?

JavaScriptTypeScriptPythonGo

The idea

Give one agent the same job in four languages and see what changes.

Each language gets a repository that starts in the same broken state and must end in the same working state. Same instructions, same model, same agent scaffold, same budget, fresh context every time. Only the language differs, so anything that moves is attributable to the language and its toolchain.

01

Same job

Byte-identical instructions in every language, and one shared verifier that tests behavior rather than style.

02

Hard enough to fail

Earlier rounds were too easy: every language passed everything, which answers nothing. The current task fails often enough to compare.

03

Calibrated before launch

Correct solutions pass, untouched starters fail the identical checks in all four languages, and deliberately broken solutions get caught.

The current task. A four-file command-line reporting tool has to stop doing money math in floating point. The agent must switch to exact arithmetic, convert currencies along the shortest rate path and reject ambiguous ones, total every parent account, round half-to-even per entry, and reject roughly thirty kinds of malformed input. The starter code fails eight of the twelve hidden checks in every language.

Results across four languages

What the data says

Success barely moved. Effort did.

Python finished everything

Python passed all 24 attempts. JavaScript passed 18, and that gap is real: the interval for the difference excludes zero, as does the smaller gap between Python and Go. TypeScript at 22 sits between them without separating from either. So there is a correctness signal here, and it is not the one a type checker would predict.

Go and TypeScript cost more steps

Go needed about 1.5 more agent steps than Python or JavaScript, and TypeScript needed about 0.7 more than either. Both effects have intervals clear of zero, and both languages cost the most tokens and money per attempt. The compile step is the obvious suspect: the two compiled languages are the two expensive ones.

A weaker model fails everywhere

The same task run on a weaker model rung passed 0/25 attempts, in every language. No language rescued it. Whether a language matters at all seems to depend on the agent already being strong enough to be in the game.

What would change this

This is one task family, one model snapshot, and one bash-only agent scaffold. The language is a bundle that also includes its toolchain, file layout, and ecosystem, so none of this is a claim about syntax. The first half of this cohort ranked Go worst on correctness and the second half did not, which is a fair warning about how far twelve attempts can be trusted.

Intervals are 95% percentile intervals from a fixed-seed 20,000-resample paired bootstrap over matched attempt blocks. The full method, the paired contrasts for every pair, and the per-case failure breakdown are in the written report.
