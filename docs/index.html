Does language choice change how well an AI agent codes?

Language AI Bench measures whether programming language changes an AI coding agent's error rate and the amount of work it takes to reach a correct solution.

The question

If the task, tests, model, and agent stay fixed, does changing the programming language change whether the agent succeeds or how it gets there?

Method

Measure productivity and errors under controlled conditions.

The benchmark gives one agent equivalent repositories and the same behavioral requirements in each language. That makes success rate and work-to-solution comparable without reducing the task to a syntax quiz.

01

Same job

The task wording and required behavior stay aligned across languages.

02

Real repository

The agent reads code, edits multiple files, runs commands, and deals with tooling feedback.

03

Shared behavioral check

One language-neutral verifier tests the running service instead of grading code style.

Example task

Prevent concurrent writers from overwriting each other.

One of the three current task families is a backend change involving state, HTTP rules, error handling, and a race condition.

Prompt excerptFull prompt ↗
“Add HTTP optimistic concurrency control. GET responses include a stable quoted ETag. Writes require If-Match. Two writes using the same tag must not both succeed.”

The existing-project version begins with a working CRUD service. The new-project version asks the agent to build the service and concurrency behavior from a minimal scaffold.

Simplified behaviorHTTP

Hidden checks also cover concurrent writes, deletion, stable tags, ordinary CRUD behavior, and regressions.

What happens in one run

One fresh agent gets one repository and one chance.

  1. 1Fresh context

    No memory from another language or attempt.

  2. 2Agent works

    It reads, edits, runs tests, and responds to compiler or runtime feedback.

  3. 3Hidden verifier

    The same external HTTP checks exercise every language implementation.

  4. 4Pass or fail

    A pass means the completed service satisfied the required behavior.

Current coverage

Four language arms.

The current study compares JavaScript, TypeScript, Python, and Go. Each language has nine prospective runs across the same three behavioral task families.

Known-good solutions pass, untouched projects fail, and seeded broken solutions are caught across all four languages. The schedule was fixed before launch and every task passed the source-integrity gate.

What comes next

Build enough evidence to detect real language effects.

  • Add dependency migration, debugging, refactoring, and non-HTTP task families.
  • Add task families where type feedback might actually prevent subtle defects.
  • Repeat across models and richer coding-agent scaffolds.
  • Measure maintenance edits, migrations, and regressions in addition to first completion.
