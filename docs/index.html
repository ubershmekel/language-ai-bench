Open coding-agent experiment

Does language choice change how well an AI agent codes?

Language AI Bench gives an autonomous coding agent the same software-engineering job in equivalent projects, then checks each result against the same behavioral contract.

See the first experiment View the source ↗

The question

If the task, tests, model, and agent stay fixed, does changing the programming language change whether the agent succeeds—or how it gets there?

JavaScriptTypeScriptPythonGo

What this benchmark is

A controlled comparison, not a language leaderboard.

A fair language study needs more than asking a model to write four unrelated snippets. This project builds equivalent repositories and asks an agent to do realistic work inside each one.

Experiment 01 · optimistic concurrency

The agent had to prevent two writers from overwriting each other.

This is a small backend task with state, HTTP rules, error handling, and a race condition—not a toy function or syntax quiz.

Prompt excerptFull prompt ↗
“Add HTTP optimistic concurrency control. GET responses include a stable quoted ETag. Writes require If-Match. Two writes using the same tag must not both succeed.”

The existing-project version begins with a working CRUD service. The new-project version asks the agent to build the service and concurrency behavior from a minimal scaffold.

What happens in one run

One fresh agent gets one repository and one chance.

  1. 1Fresh context

    No memory from another language or attempt.

  2. 2Agent works

    It reads, edits, runs tests, and responds to compiler or runtime feedback.

  3. 3Hidden verifier

    The same external HTTP checks exercise every language implementation.

  4. 4Pass or fail

    A pass means the completed service satisfied the required behavior.

First paid comparison · JavaScript vs TypeScript

The study found no winner.

All 22 balanced attempts passed. That is good news for the agent, but weak evidence for comparing the languages: the task hit a ceiling and could not separate them.

What does “6/6 passed” mean?

Six independent agent attempts were run in that condition, and all six completed the full task. It does not mean there were six test cases.

What we can say

TypeScript did not stop the agent from finishing.

Strict typing imposed no observed completion penalty in these new or existing Node projects. JavaScript also completed every attempt.

What we cannot say

We did not show that TypeScript makes agents more successful.

With 100% in every cell, there is no measured accuracy advantage to explain. Small differences in steps, tokens, cost, and time are descriptive telemetry, not a verdict.

What comes next

Make the benchmark harder before making the claim louder.

  • Run the calibrated Python and Go arms with the same agent controls.
  • Add task families where type feedback might actually prevent subtle defects.
  • Repeat across models and richer coding-agent scaffolds.
  • Measure maintenance edits, migrations, and regressions—not only first completion.
